Carbomètre — Méthodologie

Version préliminaire. La documentation complète, avec toutes les sources citées, sera publiée dans docs/METHODOLOGY.md à une étape ultérieure du développement.

Formule

energyWh      = (tokensOutEffectifs × eTokenWh + tokensIn × eTokenWh × 0.05) × pue
electricityG  = energyWh × facteur d'émission du réseau électrique / 1000
embodiedG     = (tokensOutEffectifs + tokensIn × 0.05) × empreinte matérielle par token
gCO2e         = electricityG + embodiedG

tokensOutEffectifs inclut le raisonnement caché ou visible du modèle. Le facteur d'entrée (0,05) reflète le fait que le traitement du prompt est très parallélisé, donc bien moins coûteux par token que la génération de la réponse.

Équivalent voiture

125 gCO2e/km, une moyenne pour une voiture particulière.

Limites connues

  • Le nombre de tokens est estimé à partir du nombre de caractères, pas mesuré avec le tokenizer réel du fournisseur.
  • Le raisonnement caché des modèles qui ne l'affichent pas est estimé par un multiplicateur, pas mesuré.
  • Le contexte invisible renvoyé par le fournisseur à chaque tour (historique, prompt système, documents) n'est pas comptabilisé : le résultat est donc une sous-estimation.
  • Le centre de données qui répond réellement n'est pas connu ; une région par défaut est supposée pour chaque modèle.
  • Les émissions liées à l'entraînement du modèle ne sont pas incluses.

Cet outil donne un ordre de grandeur, pas une mesure précise, et ne doit pas être utilisé pour un reporting carbone réglementaire.

Carbomètre — Methodology

Preliminary version. The full, fully-cited documentation will ship as docs/METHODOLOGY.md at a later point in development.

Formula

energyWh      = (effectiveOutputTokens × eTokenWh + tokensIn × eTokenWh × 0.05) × pue
electricityG  = energyWh × grid emission factor / 1000
embodiedG     = (effectiveOutputTokens + tokensIn × 0.05) × embodied footprint per token
gCO2e         = electricityG + embodiedG

effectiveOutputTokens includes the model's hidden or visible reasoning. The input weight (0.05) reflects that prompt processing is heavily parallelised, so far cheaper per token than generating the reply.

Car equivalent

125 gCO2e/km, a typical average passenger car.

Known limitations

  • Token counts are estimated from character length, not measured with the provider's real tokenizer.
  • Hidden reasoning on models that don't show it is estimated with a multiplier, not measured.
  • The invisible context the provider re-sends every turn (history, system prompt, documents) is not counted - the result is an underestimate.
  • The datacentre that actually answers a request is unknown; a default region is assumed per model.
  • Emissions from training the model are not included.

This tool gives an order of magnitude, not a precise measurement, and must not be used for regulatory carbon reporting.
